PYQ overview catalogue cache hits took 13 ms for a signed-out visitor. Account and learner data still use live queries.

Next.js now streams the app navigation and page headings ahead of backend data. Inline Suspense fallbacks cover the main public catalogues, Learn, Practice, Analytics and billing sections. Account navigation and credit controls wait separately for the session. Verified the production build and Chrome at 390px and 1440px with a delayed API and session.

PYQ opening now resolves the study scope without a learner lookup and uses one overview request for both the archive and its exam switch. Paper and topic feeds skip unused filter counts, and metadata reads the catalogue without fetching question bodies. Chrome opened the archive in 3.2 seconds on the first desktop navigation and 270 ms on the warm mobile navigation. In a signed-in Neon-backed paper API check, omitting unused facets reduced 17 queries to 9 and preserved the rest of the response.

Authenticated Neon traces found 35 queries on Analytics, 21 on Learn and redundant reads during question grading. Analytics now batches live activity and plan reads, at one live view query and 1.06–1.08 seconds with warm catalogue data and an explicit exam and tier. The query includes unfinished mock timers. Expired mocks are finalized under a lock and the dashboard reads again before returning scores. Public chapter mappings are cached with the catalogue. Learn reuses public catalogue metadata and frequency counts and requests only the overview fields used by the browser. PYQ multiple-choice grading uses two database statements after authentication. The browser acknowledges submission immediately and waits for the saved verdict. Profile and Practice also avoid repeated reads and unnecessary write transactions.
